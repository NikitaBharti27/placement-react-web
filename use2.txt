1. ALL COMMANDS (MAIN FIRST)
================================================================================

Here is the master list of all commands you will ever need, ordered with the most 
important command first:

--------------------------------------------------------------------------------
1. START LOCAL APP (MAIN COMMAND — RUN THIS TO WORK OR EVALUATE)
--------------------------------------------------------------------------------
   npm run dev

   - What it does: Launches the local Vite development server with Hot Module 
     Replacement (HMR).
   - URL to open: http://localhost:5173
   - Startup time: Less than 300 milliseconds.
   - Note: Keep this terminal window open while you interact with the app in your browser.

--------------------------------------------------------------------------------
2. INSTALL DEPENDENCIES (RUN FIRST IF STARTING ON A NEW LAPTOP OR FRESH CLONE)
--------------------------------------------------------------------------------
   npm install

   - What it does: Downloads all required frontend libraries from npm into your 
     `node_modules/` folder:
     * React 19 + React DOM
     * Redux Toolkit (`@reduxjs/toolkit` and `react-redux`)
     * React Router Dom v7 (`react-router-dom`)
     * Monaco Editor (`@monaco-editor/react`)
     * Microsoft Entra ID Auth (`@azure/msal-browser` and `@azure/msal-react`)
     * Tailwind CSS v4 (`tailwindcss` and `@tailwindcss/vite`)
     * Lucide Icons (`lucide-react`)
   - When to run: Only once when you clone the project, or after pulling new code.

--------------------------------------------------------------------------------
3. BUILD PRODUCTION ASSETS (RUN BEFORE DEPLOYING TO AZURE STATIC WEB APPS)
--------------------------------------------------------------------------------
   npm run build

   - What it does: Runs Vite's production compiler. Compiles, bundles, minifies, 
     and tree-shakes all JSX, CSS, and assets into the `dist/` directory.
   - Why we run it: Verifies there are 0 syntax errors, 0 broken imports, and 
     produces optimized assets ready for cloud hosting.

--------------------------------------------------------------------------------
4. CODE QUALITY & LINTING CHECK (RUN TO ENSURE CLEAN CODE STANDARDS)
--------------------------------------------------------------------------------
   npm run lint

   - What it does: Executes ESLint across all JavaScript and JSX files in `src/`.
   - Checks for: Unused variables, broken React hooks dependencies, and React 19 
     purity rules.
   - Current status: Clean! 0 errors and 0 warnings.

--------------------------------------------------------------------------------
5. PREVIEW COMPILED PRODUCTION BUILD LOCALLY
--------------------------------------------------------------------------------
   npm run preview

   - What it does: Spins up a lightweight local web server serving the compiled 
     `dist/` folder instead of dev mode.
   - Why we run it: Allows you to test real production loading speeds and verify 
     that your production build works identically to development.

--------------------------------------------------------------------------------
6. RUN LINT AND BUILD IN A SINGLE COMMAND (THE SENIOR DEVELOPER ONE-LINER)
--------------------------------------------------------------------------------
   npm run lint ; npm run build

   - On Windows PowerShell, this runs linting and immediately proceeds to building 
     assets, giving you an instant pass/fail check.

3. WHAT EXTERNAL THINGS YOU NEED TO DO BY YOURSELF
================================================================================

To ensure that evaluators, teammates, and teachers never get blocked by missing 
cloud credentials or offline servers, I designed the frontend with dual-mode 
resilience:

--------------------------------------------------------------------------------
A. ZERO-SETUP LOCAL DEVELOPMENT (WORKS 100% OUT-OF-THE-BOX RIGHT NOW!)
--------------------------------------------------------------------------------
- What this means: You DO NOT need to set up any cloud accounts, database servers, 
  or API keys to test, grade, or evaluate Phase 1 and Phase 2 today!
- Built-In Smart Fallbacks:
  * Authentication: Simulates Student OTP and Microsoft Entra ID SSO seamlessly.
  * Assessment Engine: Pre-loaded with full TCS NQT and Accenture assessment tracks.
  * Code Sandbox: Simulates isolated Docker compilation returning stdout and pass 
    rates in under 1 second without requiring local Docker daemon.
  * SQL Runner: Simulates relational queries against the test schema.
  * Async Submission Queue: Simulates Upstash QStash dispatch returning unique Job IDs.
  * Timer Sync: Simulates authoritative server clock synchronization.

However, when moving to live enterprise deployment with your team, here are the 
external items you will configure:

--------------------------------------------------------------------------------
B. CREATING YOUR `.env` FILE (FOR LIVE BACKEND & AZURE CLOUD)
--------------------------------------------------------------------------------
Create a file named `.env` in the root folder (`p:\Projects\placement-react-web\.env`):

```env
# ==============================================================================
# PLACEPREP SECURE — ENVIRONMENT CONFIGURATION
# ==============================================================================

# 1. MICROSOFT ENTRA ID (AZURE AD) CREDENTIALS (FOR INSTITUTIONAL SSO)
# Obtained from Azure Portal -> Microsoft Entra ID -> App Registrations
VITE_AZURE_CLIENT_ID=your-azure-app-client-id-here
VITE_AZURE_TENANT_ID=your-azure-tenant-id-or-common
VITE_REDIRECT_URI=http://localhost:5173

# 2. BACKEND NODE.JS EXPRESS API URL (KAIF'S SERVER)
# The base URL where Kaif's Express server listens
VITE_API_URL=http://localhost:5000/api
```

--------------------------------------------------------------------------------
C. SETTING UP MICROSOFT ENTRA ID (WHEN TEAMMATE ATANU PROVISIONS AZURE)
--------------------------------------------------------------------------------
When your cloud infrastructure lead (Atanu) sets up institutional faculty sign-in:
1. Log in to the Azure Portal: https://portal.azure.com
2. Search for "Microsoft Entra ID" in the top search bar.
3. In the left navigation menu, click "App registrations" ➔ Click "New registration".
4. Fill in the form:
   - Name: `PlacePrep Secure Web`
   - Supported Account Types: "Accounts in this organizational directory only" (Single Tenant) 
     or "Accounts in any organizational directory" (Multi-Tenant).
   - Redirect URI:
     * Select platform: `Single-page application (SPA)`
     * URI: `http://localhost:5173` (for local development)
     * Additional URI: `https://your-app.azurestaticapps.net` (for live production).
5. Click "Register".
6. In the Overview screen, copy:
   - "Application (client) ID" ➔ paste as `VITE_AZURE_CLIENT_ID` in `.env`.
   - "Directory (tenant) ID" ➔ paste as `VITE_AZURE_TENANT_ID` in `.env`.

--------------------------------------------------------------------------------
D. CONNECTING TEAMMATE KAIF'S NODE.JS BACKEND SERVER
--------------------------------------------------------------------------------
When backend developer Kaif provides the Node.js Express server:
1. Start Kaif's backend repository (typically runs on `http://localhost:5000`).
2. Make sure `VITE_API_URL=http://localhost:5000/api` is in your `.env`.
3. Our frontend API client (`src/api/client.js` and `src/api/assessmentApi.js`) 
   automatically attaches:
   - `Authorization: Bearer <jwt_token>`
   - `X-Tenant-Id: <college_tenant_id>`
   - `Idempotency-Key: sub_<examId>_<timestamp>`
4. If Kaif's server is ever stopped or down, our frontend gracefully falls back 
   to the local mock engine so you are never left with a blank screen.

--------------------------------------------------------------------------------
E. MONACO EDITOR INTERNET / CDN CONNECTIVITY
--------------------------------------------------------------------------------
- How Monaco loads: By default, `@monaco-editor/react` loads the core VS Code editor 
  engine from Microsoft's official CDN (`cdnjs.cloudflare.com` / `cdn.jsdelivr.net`).
- What you need to do: Make sure your computer is connected to the internet the first 
  time you open the editor so your browser caches the Monaco worker files. Once cached, 
  it runs smoothly.

--------------------------------------------------------------------------------
F. CONNECTING AZURE CONTAINER APPS DOCKER SANDBOX (ATANU & PANKAJ)
--------------------------------------------------------------------------------
- What this is: In production, student code is sent to an ephemeral Docker container 
  running on Azure Container Apps with gVisor sandbox security and zero internet access.
- What you need to do: This is managed by cloud infrastructure teammates Atanu and 
  Pankaj. As a frontend developer or evaluator, you only interact with the API 
  endpoint `POST /api/assessments/:id/execute`. Our frontend code already handles 
  sending the language, code, and custom inputs and displays stdout/stderr and execution times.

--------------------------------------------------------------------------------
G. RECOMMENDED BROWSER EXTENSIONS (HIGHLY RECOMMENDED FOR DEVELOPERS)
--------------------------------------------------------------------------------
- Redux DevTools Extension:
  * Install from Chrome Web Store or Edge Add-ons.
  * Press F12 in your browser and click the "Redux" tab.
  * You will see the entire live state tree:
    - `auth`: Logged in student, token, role.
    - `exam`: Active question index, answers per question ID, server timer offset, 
      and sandbox execution logs.
  * You can replay actions, inspect dispatches, and debug state in real-time!
