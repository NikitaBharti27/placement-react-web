Unlike simple online quiz apps that only support radio buttons, modern placement drives 
from Fortune 500 tech companies (TCS, Accenture, Infosys, Capgemini) evaluate 
candidates on real programming, database querying, and UI problem-solving.

What was built in Phase 2:

   Created an anti-tamper timer (`ServerExamTimer.jsx` and `useExamTimer.js`) that

   If a student alters their computer clock in Windows/Mac settings, the timer 
   instantly detects the drift and prevents cheating.

   Engineered 4 specialized evaluation interfaces:
   - MCQ Workspace: Distraction-free conceptual questions with keyboard shortcuts

     live preview iframe and automated DOM verification tests.

   Created `examSlice.js`, `examThunks.js`, and `examHooks.js` to manage active 
   question indexes, auto-saved answers, palette statuses, timer ticks, compilation 
   states, and submission receipts.

5. Production Exam Navigation & Shell:
   - Dedicated Assessment Catalog (`AssessmentsListPage.jsx`) at `/student/assessments`.
   - Full distraction-free player (`AssessmentPlayerPage.jsx`) at `/student/assessment/:assessmentId`.

2. THE BIG PICTURE: HOW PLACEPREP SECURE'S ASSESSMENT ENGINE WORKS
================================================================================

Imagine a traditional university exam: students sit in an exam hall, receive a 
printed question paper, and write their answers on paper. The proctor monitors 
the clock on the wall, and when time is up, papers are collected.

Now translate that to the modern corporate tech hiring ecosystem:
Top MNCs like Tata Consultancy Services (TCS NQT) and Accenture assess thousands 
of candidates at the same time across different cities. 

They face three major problems:
  1. The Format Problem: MCQs alone don't prove a candidate can code. But having 
     professors grade thousands of code submissions manually is impossible. 
     The platform must automatically run student code against secret test cases 
     in a secure environment.
  2. The Timer Manipulation Problem: In cheap web apps, timers run using JavaScript 
     `setInterval` based on the candidate's browser clock. A student could change 
     their computer time from 10:45 AM back to 10:00 AM to get 45 extra minutes! 
     PlacePrep Secure makes timers server-authoritative. The server holds the true 
     deadline; client clock changes have zero effect.
  3. The Variety Problem: An assessment might have 2 MCQs, followed by a graph 
     traversal coding problem, followed by an employee salary SQL query, followed by 
     a CSS flexbox layout challenge. The frontend must seamlessly adapt its interface 
     for each question without reloading the webpage.

That is what Phase 2 accomplishes: an enterprise-grade, multi-format evaluation engine 
that feels as smooth and professional as LeetCode, HackerRank, and VS Code combined.

3. BEGINNER'S GUIDE: EXPLAINING EVERY TECH STACK & CONCEPT WITH REAL-WORLD ANALOGIES
================================================================================

If you are new to web development or modern software engineering, here is a simple, 
friendly explanation of every technology, pattern, and tool used in Phase 2.

--------------------------------------------------------------------------------
3.1 WHAT IS AN ASSESSMENT ENGINE? (THE DIGITAL EXAM HALL)
--------------------------------------------------------------------------------
- What it is: An assessment engine is the software system responsible for delivering 
  exam questions, recording student answers in real-time, enforcing time limits, 
  and packaging responses for automated grading.
- The Real-World Analogy: Think of it like a digital exam desk. When you sit down, 
  the desk automatically presents the exact tools you need: a scratchpad for MCQs, 
  a code compiler for coding questions, or a database terminal for SQL queries.

--------------------------------------------------------------------------------
3.2 WHAT IS MONACO EDITOR? (THE ENGINE BEHIND VS CODE)
--------------------------------------------------------------------------------
- What it is: Monaco Editor is the open-source code editor library developed by 
  Microsoft that powers Visual Studio Code (VS Code).
- The Problem without Monaco: If you use a regular HTML `<textarea>` for code, you get 
  no line numbers, no syntax coloring, no auto-indentation, no bracket matching, 
  and pressing the Tab key accidentally moves focus away to the next button!
- How Monaco Solves It: Monaco gives the candidate a genuine VS Code experience 
  inside the browser tab:
  * Syntax highlighting for Python, JavaScript, Java, C++, and SQL.
  * Autocomplete suggestions and parameter hints.
  * Bracket pair colorization (matching `{}` and `()` in distinct colors).
  * Minimap and line numbers.
  * In Phase 2, we integrated Monaco via `@monaco-editor/react` inside 
    `src/components/assessment/editor/MonacoCodeEditor.jsx`.

--------------------------------------------------------------------------------
3.3 WHAT IS MULTI-FORMAT EVALUATION? (WHY MNCs STOPPED USING JUST MCQs)
--------------------------------------------------------------------------------
- In our platform, an exam can contain 4 distinct question formats:
  1. `MCQ` (Multiple-Choice Questions):
     * Used for testing aptitude, logical reasoning, and algorithmic complexity.
     * Features keyboard shortcuts (A, B, C, D or 1, 2, 3, 4) for rapid answering.
  2. `SIMULATION` (Story-Based Algorithmic Problems):
     * Instead of "Reverse this array", candidates solve practical corporate scenarios: 
       "You are routing autonomous electric delivery pods across warehouse hubs. 
       Find the route that minimizes maximum battery jump effort."
     * Candidates can choose their favorite language (Python, JavaScript, Java, C++).
  3. `SQL_TASK` (Database Query Challenges):
     * Evaluates relational database skills (Joins, Aggregations, Window Functions).
     * Candidates can click tables in our Schema Inspector to see columns, primary keys, 
       and sample tuples, and compare their output against the expected result.
  4. `UI_TASK` (Interactive Frontend Engineering):
     * Candidates are given a broken or unstyled component (e.g. a candidate profile card).
     * They edit HTML, CSS, and JS in tabs and see their changes update instantly inside 
       a live sandboxed preview.

--------------------------------------------------------------------------------
3.4 WHAT IS SERVER-AUTHORITATIVE TIMING? (CLOCK TOWER VS PERSONAL WRISTWATCH)
--------------------------------------------------------------------------------
- The Client-Timer Flaw:
  Many basic websites calculate remaining time like this:
  `let timeLeft = 60 * 60; setInterval(() => { timeLeft--; }, 1000);`
  If the student freezes the browser tab or changes their operating system clock, 
  they can cheat and buy unlimited extra time.
- The Server-Authoritative Solution (The Master Clock Tower):
  * When the exam starts, our Node.js server sends two numbers:
    1. `serverCurrentTime` (e.g. 10:00:00 AM)
    2. `serverDeadline` (e.g. 11:30:00 AM)
  * The frontend calculates the clock drift: `offset = serverCurrentTime - clientCurrentTime`.
  * Even if the student changes their computer clock, the formula 
    `remaining = (deadline - (Date.now() + offset))` detects the tampering.
  * Every 45 seconds, and whenever the candidate switches back to the tab, a silent 
    heartbeat pings the server to recalibrate drift.
  * When `remaining <= 0`, the exam instantly locks down and auto-submits.

--------------------------------------------------------------------------------
3.5 WHAT IS A DOCKER SANDBOX & GVISOR CONTAINER? (THE HAZMAT WARD)
--------------------------------------------------------------------------------
- The Danger of Untrusted Code:
  When a candidate writes Python or C++ code and clicks "Run", that code could be 
  malicious! A student could write: `import os; os.system("rm -rf /")` or try to 
  hack the university server or read other students' files.
- How Docker & gVisor Solve It:
  * Student code is never run directly on the main web server.
  * It is sent to an isolated, ephemeral Docker container running on Azure Container Apps.
  * The container has ZERO internet access (no egress network), strictly limited 
    CPU and RAM (e.g. 256MB), a read-only filesystem, and a strict 2.0-second timeout.
  * The sandbox runs the code against test cases, captures standard output (stdout) 
    or errors (stderr), destroys the container, and sends the score back to the frontend.

--------------------------------------------------------------------------------
3.6 WHAT IS ASYNCHRONOUS QUEUING? (UPSTASH QSTASH & FAST-FOOD ANALOGY)
--------------------------------------------------------------------------------
- The 1,000 Concurrent Submissions Problem:
  Imagine 1,000 engineering students taking a campus placement exam simultaneously. 
  At 11:30 AM, all 1,000 students click "Submit Exam" at the exact same second! 
  If the server tried to compile 1,000 programs at once, the server would crash.
- The Fast-Food Order Counter Analogy (Upstash QStash + Celery):
  * When you order at McDonald's, the cashier doesn't cook your burger. The cashier gives 
    you an order ticket (Job ID) and sends the ticket to the kitchen queue.
  * In PlacePrep Secure, when you click "Submit", Node.js instantly accepts your answers, 
    writes them to PostgreSQL, and pushes an execution job to Upstash QStash (a cloud 
    message queue).
  * Background Python Celery workers take jobs from the queue one by one, execute them in 
    Docker containers, and save the score.
  * The frontend receives an instant `jobId` confirmation without waiting or freezing!

--------------------------------------------------------------------------------
3.7 WHAT IS AN IFRAME SANDBOX FOR LIVE UI PREVIEWS? (THE BULLETPROOF WINDOW)
--------------------------------------------------------------------------------
- For UI engineering tasks, candidates write HTML, CSS, and JavaScript.
- If we rendered their HTML/JS directly inside our main React application, their code 
  could accidentally overwrite PlacePrep's Navbar, break styles, or execute scripts 
  stealing session tokens!
- We use an `<iframe>` with the HTML5 `sandbox="allow-scripts"` attribute.
- Think of an iframe sandbox like a bulletproof glass window: you can see what is happening 
  inside the room, but anything inside that room cannot reach out and touch the rest of 
  the building.

--------------------------------------------------------------------------------
3.8 WHAT IS AUTOMATED DOM TESTING? (THE AUTOMATED QUALITY INSPECTOR)
--------------------------------------------------------------------------------
- In UI tasks, how do we know if the student completed the task correctly?
- In `UiTaskWorkspace.jsx`, when the student clicks "Verify UI Requirements", our 
  verification engine automatically inspects the candidate's code:
  * Does the card use flexbox/grid layout?
  * Does the status badge have the correct emerald background `#d1fae5`?
  * Does the button have hover and focus transition styles?
  * Does clicking the button toggle the text to "✓ Verified"?
- Each criterion turns from a gray circle into a glowing green checkmark with an 
  updated score badge (e.g. "4 / 4 Requirements Passed").

--------------------------------------------------------------------------------
3.9 WHAT IS ACTIVE EXAM REDUX STATE (`examSlice.js`)? (THE DIGITAL ANSWER BOOKLET)
--------------------------------------------------------------------------------
- In Phase 1, we explained Redux as the "Central Bank" for state.
- In Phase 2, `examSlice.js` acts as the candidate's digital answer booklet:
  * It stores the active question list.
  * It records every keystroke, option click, or SQL query per question ID.
  * Even if the student navigates between Question 1 and Question 5, their written 
    code or selected options are never lost.
  * It tracks whether a question has been marked for later review.

--------------------------------------------------------------------------------
3.10 WHAT IS A QUESTION PALETTE & STATUS MATRIX? (THE OMR BUBBLE TRACKER)
--------------------------------------------------------------------------------
- In competitive examinations (like JEE, GATE, CAT), candidates have a grid of numbered 
  buttons representing all questions.
- Our `QuestionPalette.jsx` displays color-coded statuses:
  * Green: Question is answered.
  * Purple: Question is marked for review.
  * Purple with dot: Question is answered AND marked for review.
  * Slate Gray: Question has been visited but not answered.
  * Dark Gray: Question has not been visited yet.
  * Indigo Ring: The question you are currently viewing.
- Candidates can filter by "Answered", "Unanswered", or "Review" and jump to any question 
  with a single click.

--------------------------------------------------------------------------------
3.11 WHAT IS IDEMPOTENT SUBMISSION?
--------------------------------------------------------------------------------
- What is Idempotency?: An operation is "idempotent" if performing it multiple times 
  produces the exact same result as performing it once.
- Why it matters in exams: If a student's internet fluctuates and they click "Submit" 
  three times, or their browser auto-retries a failed network packet, we must NEVER 
  create 3 separate duplicate exam submissions in the database!
- Our API attaches an `Idempotency-Key: sub_<assessmentId>_<timestamp>` header. 
  The server recognizes duplicate submissions and safely returns the existing job receipt.

5. HOW THE ASSESSMENT ENGINE WORKS UNDER THE HOOD (STEP-BY-STEP DATA FLOWS)
================================================================================

Here is the exact lifecycle of data during an assessment:

--------------------------------------------------------------------------------
FLOW A: CANDIDATE LAUNCHES ASSESSMENT & SYNCS SERVER CLOCK
--------------------------------------------------------------------------------
1. Student clicks "Start Exam" on the TCS NQT card on the Student Dashboard.
2. React Router navigates to `/student/assessment/tcs-nqt-tech-01`.
3. `AssessmentPlayerPage.jsx` mounts and dispatches `loadAssessment("tcs-nqt-tech-01")`.
4. `examThunks.js` calls `assessmentApi.getAssessmentById("tcs-nqt-tech-01")`.
5. The API returns the assessment payload containing 5 multi-format questions, 
   `serverCurrentTime`, and `serverDeadline`.
6. `examSlice.js` receives `setAssessment`:
   * Calculates `serverTimeOffset = serverCurrentTime - clientNow`.
   * Calculates `remainingSeconds = (serverDeadline - (clientNow + offset)) / 1000`.
   * Sets question #1 as `currentQuestionIndex = 0` and marks it `VISITED`.
   * Pre-populates starter code into `state.exam.answers`.
7. `ServerExamTimer.jsx` begins ticking down every 1 second.

--------------------------------------------------------------------------------
FLOW B: CANDIDATE SOLVES SIMULATION CODING (MONACO -> SANDBOX -> TEST CASES)
--------------------------------------------------------------------------------
1. Candidate navigates to Question #3 (Fleet Routing Simulation problem).
2. `AssessmentPlayerPage` inspects `currentQuestion.type === 'SIMULATION'` and renders 
   `<SimulationWorkspace />`.
3. Left pane displays the logistics fleet story, constraints, and sample cases.
4. Right pane renders `<MonacoCodeEditor />` pre-loaded with Python 3.11 starter code.
5. As candidate types, `handleCodeChange` dispatches `saveAnswer`:
   * Updates `state.exam.answers['q-tcs-03'].code`.
   * Status bar shows "Auto-saved in Redux" and character count.
6. Candidate clicks "Run Sample Tests":
   * Workspace dispatches `executeCode({ assessmentId, questionId, code, language })`.
   * `assessmentApi.runCodeSandbox` sends payload to the isolated Docker sandbox.
   * In 184ms (<2s), the sandbox finishes and returns stdout logs and test results.
   * `examSlice.js` updates `state.exam.execution['q-tcs-03']`.
   * The execution drawer opens displaying green `3/3 Tests Passed` badges and stdout.

--------------------------------------------------------------------------------
FLOW C: CANDIDATE SOLVES SQL TASK (SCHEMA INSPECTOR -> EXECUTION -> OUTPUT DIFF)
--------------------------------------------------------------------------------
1. Candidate navigates to Question #4 (Department Top 2 Earners).
2. `AssessmentPlayerPage` renders `<SqlTaskWorkspace />`.
3. Left pane renders the Database Schema Inspector:
   * Candidate clicks between `employees` and `departments` table tabs.
   * Schema inspector shows column names (`salary`, `department_id`), data types, 
     primary keys, and sample database tuples.
4. Right pane displays the Monaco SQL editor.
5. Candidate enters their query and clicks "Execute Query".
6. In ~82ms, the test query runs and returns tabular results:
   * Results drawer renders student's output table: `department_name`, `employee_name`, `salary`, `salary_rank`.
   * Compares with expected output and flashes green: `✓ Output Matches Expected`.

--------------------------------------------------------------------------------
FLOW D: CANDIDATE SOLVES UI TASK (CODE TABS -> LIVE IFRAME -> DOM CHECK)
--------------------------------------------------------------------------------
1. Candidate navigates to Question #5 (Placement Candidate Card).
2. `AssessmentPlayerPage` renders `<UiTaskWorkspace />`.
3. Left pane displays the UI Brief and 4 acceptance requirements.
4. Right pane provides 3 code tabs: `index.html`, `styles.css`, `script.js`.
5. Below the editor, an `<iframe sandbox="allow-scripts">` renders the live preview.
6. When the candidate edits CSS (e.g. changing badge padding or colors), the preview 
   updates instantly.
7. Candidate clicks "Verify UI Requirements":
   * Engine evaluates DOM assertions.
   * Checklist items update to green checkmarks (`4 / 4 Passed`).

--------------------------------------------------------------------------------
FLOW E: AUTHORITATIVE TIMER HEARTBEAT & CLOCK DRIFT CORRECTION
--------------------------------------------------------------------------------
1. While the exam runs, `useExamTimer` hook maintains an active interval.
2. Every 45 seconds, or whenever the candidate switches away and returns to the tab 
   (`document.visibilitychange === 'visible'`), `syncExamTimer` executes.
3. Node.js backend returns its authoritative server timestamp.
4. `updateAuthoritativeServerTime` recalibrates `serverTimeOffset`.
5. If remaining time falls below 10 minutes, the timer switches to amber.
6. If remaining time falls below 2 minutes, the timer pulses with a red alert badge.
7. When remaining time hits 0, `isTimeUp = true` triggers auto-lock.

--------------------------------------------------------------------------------
