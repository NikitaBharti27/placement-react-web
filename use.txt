1. ALL COMMANDS (MAIN FIRST)
--------------------------------------------------------------------------------

1. START THE APP (MAIN COMMAND)
   npm run dev
   - Starts the local Vite development server with Hot Module Replacement (HMR).
   - Local URL: http://localhost:5173

2. INSTALL DEPENDENCIES (RUN IF CLONING FRESH REPO)
   npm install
   - Installs all React, Redux, React Router, MSAL, and Tailwind packages.

3. PRODUCTION BUILD (TEST BEFORE DEPLOYING)
   npm run build
   - Compiles and minifies all code into the `dist/` directory.
   - Ensures zero TypeScript/JSX syntax errors exist.

4. CODE QUALITY & LINTING CHECK
   npm run lint
   - Runs ESLint across all files to detect syntax issues or unused variables.

5. PREVIEW PRODUCTION BUILD LOCALLY
   npm run preview
   - Serves the production build (`dist/`) on a local web server to test real speed.


--------------------------------------------------------------------------------
2. HOW TO RUN THE APP (STEP-BY-STEP)
--------------------------------------------------------------------------------

PREREQUISITE:
- Node.js (version 20+ or 22+ recommended)
- Verify Node version:
    node -v
    npm -v

STEPS:
Step 1: Open your terminal (PowerShell, Command Prompt, or VS Code Terminal) in:
        p:\Projects\placement-react-web

Step 2: Run the dev server:
        npm run dev

Step 3: Open your web browser (Chrome, Edge, Brave, or Firefox) and visit:
        http://localhost:5173

Step 4: You will see the PlacePrep Secure landing page!

3. WHAT EXTERNAL THINGS YOU NEED TO DO BY YOURSELF
--------------------------------------------------------------------------------

The frontend is built to run 100% OUT-OF-THE-BOX in development mode with built-in 
mock authentication so you can test all features right now. 

However, for live production and external cloud services, here are the things 
you will set up:

================================================================================
A. CREATE A `.env` FILE (OPTIONAL FOR DEV, REQUIRED FOR LIVE AZURE / BACKEND)
================================================================================
Create a file named `.env` in the root folder (`p:\Projects\placement-react-web\.env`):

```env
# 1. Microsoft Entra ID (Azure AD) Credentials (for Live Faculty SSO)
VITE_AZURE_CLIENT_ID=your-azure-app-client-id-here
VITE_AZURE_TENANT_ID=your-azure-tenant-id-or-common
VITE_REDIRECT_URI=http://localhost:5173

# 2. Backend Node.js API URL (Kaif's Server)
VITE_API_URL=http://localhost:5000/api
```

* NOTE: If you do NOT provide these environment variables, do not worry! 
  Our code has built-in smart fallbacks that automatically simulate Entra ID and 
  OTP login so you never get blocked while developing or evaluating.


================================================================================
B. HOW TO GET MICROSOFT ENTRA ID CREDENTIALS (WHEN READY FOR AZURE PROD)
================================================================================
When your cloud team (Atanu / Ayan) or college IT department provisions Azure:
1. Go to Azure Portal: https://portal.azure.com
2. Search for "Microsoft Entra ID" (formerly Azure Active Directory).
3. Click "App registrations" in the left sidebar ➔ Click "New registration".
4. Name: "PlacePrep Secure Web"
5. Supported account types: "Accounts in this organizational directory only" (or Multitenant).
6. Redirect URI:
   - Platform: Select "Single-page application (SPA)"
   - URI: `http://localhost:5173` (for local dev) and your Azure Static Web Apps URL (for prod).
7. Click "Register".
8. Copy the "Application (client) ID" and "Directory (tenant) ID" into your `.env` file!


================================================================================
C. RUNNING KAIF'S BACKEND SERVER (WHEN CONNECTING END-TO-END)
================================================================================
When teammate Kaif provides the Node.js backend:
1. Start Kaif's Express server (usually runs on `http://localhost:5000`).
2. Our frontend `src/api/client.js` is already pre-configured to send requests to 
   `http://localhost:5000/api`.
3. If the backend is offline, the frontend seamlessly switches to mock data mode.


================================================================================
D. INSTALL REDUX DEVTOOLS EXTENSION (HIGHLY RECOMMENDED FOR DEVELOPERS)
================================================================================
- Why: It lets you visually inspect the entire Redux state (`auth.user`, `auth.role`, 
  `auth.token`) and replay dispatched actions in real-time inside your browser.
- How: 
  * Chrome/Edge: Search the Chrome Web Store for "Redux DevTools" and click "Add to Chrome".
  * Open DevTools in browser (F12) ➔ Click the "Redux" tab!
